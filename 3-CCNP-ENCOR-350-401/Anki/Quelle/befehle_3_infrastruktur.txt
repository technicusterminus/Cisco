# 3.1.a | Befehle: Paketweiterleitung, MAC-Tabelle und SDM
S: https://www.cisco.com/c/en/us/support/switches/catalyst-9300-series-switches/products-command-reference-list.html | Cisco Catalyst 9300: Command References

Q: Wie legst du ein VLAN an und gibst ihm einen Namen?
A:
```
vlan <vlan-id>
 name <vlan-name>
```
**Modus:** global, dann VLAN-Modus. Das VLAN ist sofort aktiv und erscheint in `show vlan brief`.
T: Befehl Leicht

Q: Wie machst du einen Switch-Port zum Access-Port in einem bestimmten VLAN?
A:
```
switchport mode access
switchport access vlan {<vlan-id> | name <vlan-name>}
```
**Modus:** Interface. Neuere IOS-XE-Versionen akzeptieren statt der ID auch den VLAN-Namen.
T: Befehl Leicht

Q: Wie trägst du eine MAC-Adresse statisch für ein VLAN und ein Interface in die MAC-Tabelle ein?
A:
```
mac address-table static <mac-adresse> vlan <vlan-id> interface <interface-id>
```
**Modus:** global. Statische Einträge altern nicht und werden nicht durch Lernen an einem anderen Port überschrieben.
T: Befehl Mittel

Q: Mit welchem Befehl löschst du dynamisch gelernte MAC-Adressen, wahlweise nach Adresse, Interface oder VLAN?
A:
```
clear mac address-table dynamic [address <mac-adresse> | interface <interface-id> | vlan <vlan-id>]
```
**Modus:** privilegiert. Ohne Zusatz verschwinden alle dynamischen Einträge, die statischen bleiben.
T: Befehl Mittel

Q: Welcher Befehl zeigt die MAC-Tabelle, optional nur eine Adresse, nur dynamische Einträge oder nur ein VLAN?
A:
```
show mac address-table [address <mac-adresse> | dynamic | vlan <vlan-id>]
```
**Modus:** privilegiert. Springt eine MAC zwischen zwei Ports, deutet das auf eine Schleife oder eine doppelte Adresse hin.
T: Befehl Leicht

Q: Welcher Befehl zeigt, wie viele MAC-Adressen pro VLAN gelernt sind und wie viel Platz die Tabelle noch hat?
A:
```
show mac address-table count
```
**Modus:** privilegiert. Hilft, wenn die CAM-Tabelle volläuft (MAC-Flooding).
T: Befehl Mittel

Q: Wie gibst du einem Interface eine IPv4-Adresse?
A:
```
ip address <ip-adresse> <subnetzmaske>
```
**Modus:** Interface. Auf einem Switch-Port vorher `no switchport`, sonst nur auf SVIs.
T: Befehl Leicht

Q: Wie gibst du einem Interface eine zusätzliche IPv4-Adresse aus einem zweiten Subnetz?
A:
```
ip address <ip-adresse> <subnetzmaske> secondary
```
**Modus:** Interface. OSPF bildet über sekundäre Adressen keine Nachbarschaft, bewirbt das Netz aber.
T: Befehl Mittel

Q: Wie gibst du einem Interface eine IPv6-Adresse mit Präfixlänge?
A:
```
ipv6 address <ipv6-adresse>/<präfixlänge>
```
**Modus:** Interface. Fürs Routing zusätzlich global `ipv6 unicast-routing`.
T: Befehl Leicht

Q: Wie änderst du auf einem Catalyst-Switch die Aufteilung der TCAM-Ressourcen (SDM-Template)?
A:
```
sdm prefer {vlan | advanced}
```
**Modus:** global. Greift erst nach `reload`. `vlan` gibt mehr Platz für MAC-Adressen, `advanced` für Routen, ACLs und QoS. Welche Templates eine Plattform kennt, zeigt `sdm prefer ?`.
T: Befehl Mittel

Q: Welcher Befehl zeigt das aktive SDM-Template und wie viele Einträge es für MAC, Routen und ACLs vorsieht?
A:
```
show sdm prefer
```
**Modus:** privilegiert. Zeigt auch, welches Template nach dem nächsten Neustart gilt.
T: Befehl Mittel

Q: Welcher Befehl zeigt alle Trunk-Ports mit den VLANs, die sie erlauben und weiterleiten?
A:
```
show interfaces trunk
```
**Modus:** privilegiert. Die letzte Spalte „forwarding state and not pruned“ zeigt, was wirklich über den Trunk läuft.
T: Befehl Leicht

Q: Welcher Befehl zeigt die VLANs mit ihren Access-Ports, wahlweise kurz, einzeln oder als Zusammenfassung?
A:
```
show vlan [brief | id <vlan-id> | name <vlan-name> | summary]
```
**Modus:** privilegiert. `summary` zählt nur die VLANs, `brief` zeigt pro VLAN die Ports.
T: Befehl Leicht

Q: Welcher Befehl zeigt Status, Duplex, Speed und VLAN aller Ports in einer Tabelle?
A:
```
show interfaces status
```
**Modus:** privilegiert. Statt einer VLAN-Nummer steht dort „trunk“ oder „routed“, wenn der Port kein Access-Port ist.
T: Befehl Leicht

Q: Welcher Befehl zeigt die Layer-2-Konfiguration eines einzelnen Switch-Ports, etwa Admin- und Betriebsmodus?
A:
```
show interfaces <interface-id> switchport
```
**Modus:** privilegiert. Zeigt auch Access-VLAN, natives VLAN, Voice-VLAN und ob DTP verhandelt.
T: Befehl Mittel

# 3.2.a | Befehle: RIB, CEF und statische Routen
S: https://www.cisco.com/c/en/us/support/ios-nx-os-software/ios-xe-17/products-command-reference-list.html | Cisco IOS XE 17: Command References

Q: Welcher Befehl zeigt die Forwarding Information Base (CEF) für ein Präfix?
A:
```
show ip cef [<präfix> [<maske>]] [detail]
```
**Modus:** privilegiert. Die FIB wird aus der RIB gebaut. Fehlt ein Eintrag hier, leitet die Hardware nicht weiter.
T: Befehl Mittel

Q: Welcher Befehl zeigt die CEF-Adjazenztabelle mit den vorgefertigten Layer-2-Headern?
A:
```
show adjacency [<interface>] [detail]
```
**Modus:** privilegiert. Die Adjazenzen entstehen aus ARP- und ND-Einträgen.
T: Befehl Schwer

Q: Mit welchem Befehl prüfst du, über welchen Pfad CEF ein bestimmtes Quell-Ziel-Paar bei ECMP schickt?
A:
```
show ip cef exact-route <quell-ip> <ziel-ip>
```
**Modus:** privilegiert. Zeigt das Ausgangsinterface, das der Hash für genau diesen Flow wählt.
T: Befehl Schwer

Q: Welcher Befehl zeigt, wie viele Routen jeder Routing-Quelle in der RIB stehen?
A:
```
show ip route summary
```
**Modus:** privilegiert. Gut für einen schnellen Vergleich vor und nach einer Änderung.
T: Befehl Mittel

Q: Wie legst du eine statische Route mit Ausgangsinterface und Next Hop an?
A:
```
ip route <zielnetz> <maske> <interface> <next-hop-ip>
```
**Modus:** global. Nur mit Interface und ohne Next Hop würde der Router auf Ethernet für jedes Ziel ARP fragen (Proxy ARP).
T: Befehl Mittel

Q: Wie legst du eine Floating Static Route als Backup für eine dynamisch gelernte Route an?
A:
```
ip route <zielnetz> <maske> <next-hop-ip> <admin-distanz>
```
**Modus:** global. Die Distanz muss höher sein als die des Protokolls, z. B. 130 für ein Backup zu OSPF (110).
T: Befehl Mittel

Q: Wie legst du eine Route auf Null0 an, um ein Summary zu verankern oder Verkehr zu verwerfen?
A:
```
ip route <zielnetz> <maske> Null0
```
**Modus:** global. Pakete zu genaueren, nicht existierenden Zielen werden verworfen statt der Default-Route zu folgen.
T: Befehl Mittel

Q: Wie legst du eine IPv6-Default-Route über einen Link-Local-Next-Hop an?
A:
```
ipv6 route ::/0 <interface> <fe80-adresse>
```
**Modus:** global. Mit Link-Local-Next-Hop ist das Interface Pflicht.
T: Befehl Mittel

# 3.1.a | Befehle: 802.1Q-Trunks, DTP und VTP
S: https://www.cisco.com/c/en/us/support/switches/catalyst-9300-series-switches/products-command-reference-list.html | Cisco Catalyst 9300: Command References

Q: Wie konfigurierst du einen Port als Trunk?
A:
```
switchport mode trunk
```
**Modus:** Interface. Auf Switches, die noch ISL kennen, vorher `switchport trunk encapsulation dot1q`.
T: Befehl Leicht

Q: Wie änderst du das native VLAN eines Trunks?
A:
```
switchport trunk native vlan <vlan-id>
```
**Modus:** Interface. Beide Seiten müssen übereinstimmen, sonst laufen ungetaggte Frames ins falsche VLAN.
T: Befehl Mittel

Q: Wie begrenzt du die VLANs auf einem Trunk, und wie fügst du eines hinzu oder entfernst eines?
A:
```
switchport trunk allowed vlan <liste>
switchport trunk allowed vlan {add | remove} <vlan-id>
```
**Modus:** Interface. Falle: Ohne `add` ersetzt der Befehl die gesamte Liste.
T: Befehl Mittel

Q: Wie schaltest du DTP auf einem Port ab?
A:
```
switchport nonegotiate
```
**Modus:** Interface. Nur zusammen mit festem `switchport mode trunk` oder `access` möglich.
T: Befehl Mittel

Q: Wie sorgst du dafür, dass auch das native VLAN auf allen Trunks getaggt wird?
A:
```
vlan dot1q tag native
```
**Modus:** global. Schützt vor VLAN-Hopping per Double Tagging.
T: Befehl Schwer

Q: Wie stellst du einen Switch auf VTP Version 3 im Transparent-Modus um?
A:
```
vtp version 3
vtp mode transparent
```
**Modus:** global. Transparent übernimmt keine VTP-Updates, reicht sie aber weiter. `vtp mode off` reicht sie nicht weiter.
T: Befehl Mittel

Q: Wie legst du VTP-Domäne und Passwort fest?
A:
```
vtp domain <name>
vtp password <passwort>
```
**Modus:** global. Server und Clients tauschen nur Updates aus, wenn Domäne und Passwort gleich sind.
T: Befehl Mittel

Q: Wie machst du einen Switch unter VTPv3 zum Primary Server, der VLANs verteilen darf?
A:
```
vtp primary
```
**Modus:** privilegiert (EXEC). Bei VTPv3 darf nur der Primary Server die VLAN-Datenbank ändern.
T: Befehl Schwer

Q: Welcher Befehl zeigt VTP-Version, Domäne, Modus und Revisionsnummer?
A:
```
show vtp status
```
**Modus:** privilegiert. Eine höhere Revisionsnummer überschreibt bei VTPv1/v2 die VLAN-Datenbank anderer Switches.
T: Befehl Mittel

# 3.1.b | Befehle: EtherChannel
S: https://www.cisco.com/c/en/us/support/switches/catalyst-9300-series-switches/products-command-reference-list.html | Cisco Catalyst 9300: Command References

Q: Wie bündelst du Ports per LACP und lässt den Switch aktiv verhandeln?
A:
```
channel-group <nummer> mode active
```
**Modus:** Interface (auf allen Member-Ports). `passive` wartet nur. Active–Active und Active–Passive bilden ein Bündel.
T: Befehl Leicht

Q: Wie bündelst du Ports per PAgP?
A:
```
channel-group <nummer> mode {desirable | auto}
```
**Modus:** Interface. Desirable verhandelt aktiv, Auto wartet. Auto–Auto bildet kein Bündel.
T: Befehl Mittel

Q: Wie bildest du ein statisches Bündel ohne LACP oder PAgP?
A:
```
channel-group <nummer> mode on
```
**Modus:** Interface. Beide Seiten `on`. Ein `on` gegen `active` kommt nicht zustande.
T: Befehl Mittel

Q: Wie baust du einen Layer-3-Port-Channel?
A:
```
interface range <ports>
 no switchport
 channel-group <nummer> mode active
interface port-channel <nummer>
 ip address <ip-adresse> <maske>
```
**Modus:** Interface. `no switchport` zuerst auf den Membern, sonst entsteht ein Layer-2-Port-Channel.
T: Befehl Schwer

Q: Wie stellst du die Lastverteilung eines EtherChannels auf Quell- und Ziel-IP um?
A:
```
port-channel load-balance src-dst-ip
```
**Modus:** global. Gilt für alle Port-Channels des Switches. Prüfen mit `show etherchannel load-balance`.
T: Befehl Mittel

Q: Welcher Befehl zeigt alle Port-Channels mit Protokoll und Member-Status?
A:
```
show etherchannel summary
```
**Modus:** privilegiert. Flags: P gebündelt, I eigenständig, s suspendiert, D down, SU/RU Layer 2 oder 3 und in Betrieb.
T: Befehl Leicht

Q: Welcher Befehl zeigt die LACP-Partner mit System-ID, Port-Priorität und Flags?
A:
```
show lacp neighbor
```
**Modus:** privilegiert. Für PAgP: `show pagp neighbor`.
T: Befehl Mittel

Q: Wie legst du fest, welcher Switch bei LACP über aktive und Standby-Links entscheidet?
A:
```
lacp system-priority <wert>
```
**Modus:** global. Kleiner gewinnt. Pro Port beeinflusst `lacp port-priority`, welche Links aktiv werden.
T: Befehl Schwer

Q: Wie beschränkst du einen LACP-Port-Channel auf vier aktive Links, weitere werden Hot Standby?
A:
```
lacp max-bundle 4
```
**Modus:** Port-Channel-Interface. Die Ports mit der besten Priorität werden aktiv.
T: Befehl Schwer

Q: Wie legst du fest, dass ein Port-Channel erst ab zwei aktiven Links up geht?
A:
```
port-channel min-links 2
```
**Modus:** Port-Channel-Interface. Verhindert, dass ein halber Port-Channel zu viel Verkehr anzieht.
T: Befehl Schwer

Q: Wie lässt du LACP jede Sekunde statt alle 30 Sekunden PDUs senden?
A:
```
lacp rate fast
```
**Modus:** Interface. Fehler werden nach 3 Sekunden statt nach 90 Sekunden erkannt.
T: Befehl Schwer

# 3.1.c | Befehle: Spanning Tree, RSTP und Schutzfunktionen
S: https://www.cisco.com/c/en/us/support/switches/catalyst-9300-series-switches/products-command-reference-list.html | Cisco Catalyst 9300: Command References

Q: Wie wechselst du den Spanning-Tree-Modus des Switches?
A:
```
spanning-tree mode {pvst | rapid-pvst | mst}
```
**Modus:** global. Ein Wechsel startet alle STP-Instanzen neu, das unterbricht kurz den Verkehr.
T: Befehl Leicht

Q: Wie machst du einen Switch für ein VLAN zur primären oder sekundären Root Bridge?
A:
```
spanning-tree vlan <vlan-id> root {primary | secondary}
```
**Modus:** global. Ein Makro: Es setzt die Priorität einmalig auf 24576 bzw. 28672 oder knapp unter die aktuelle Root.
T: Befehl Leicht

Q: Wie setzt du die Bridge-Priorität direkt?
A:
```
spanning-tree vlan <vlan-id> priority <wert>
```
**Modus:** global. Nur Vielfache von 4096, weil die unteren 12 Bit die VLAN-ID tragen (Extended System ID).
T: Befehl Mittel

Q: Wie änderst du die Port-Kosten eines Ports für ein VLAN?
A:
```
spanning-tree vlan <vlan-id> cost <kosten>
```
**Modus:** Interface. Wirkt auf den Weg dieses Switches zur Root, also auf die Wahl seines Root Ports.
T: Befehl Mittel

Q: Wie beeinflusst du, welchen Port der Nachbar-Switch als Root Port wählt, wenn beide Wege gleich teuer sind?
A:
```
spanning-tree vlan <vlan-id> port-priority <wert>
```
**Modus:** Interface, auf dem Switch näher an der Root. Vielfache von 16, kleiner gewinnt. Der Nachbar sieht den Wert in der BPDU.
T: Befehl Schwer

Q: Wie stellst du die STP-Kosten auf die lange Methode (32 Bit) um?
A:
```
spanning-tree pathcost method long
```
**Modus:** global. Nötig, damit 10 und 100 Gbit/s unterscheidbare Kosten bekommen. Auf allen Switches gleich setzen.
T: Befehl Schwer

Q: Wie schaltest du PortFast an einem Endgeräte-Port ein?
A:
```
spanning-tree portfast [edge]
```
**Modus:** Interface. Neuere Versionen verlangen `edge`. Für einen Trunk zu einem Server: `spanning-tree portfast edge trunk`.
T: Befehl Leicht

Q: Wie schaltest du PortFast global für alle Access-Ports ein?
A:
```
spanning-tree portfast [edge] default
```
**Modus:** global. Trunks bleiben ausgenommen.
T: Befehl Mittel

Q: Wie aktivierst du BPDU Guard auf einem Port und global für alle PortFast-Ports?
A:
```
spanning-tree bpduguard enable
spanning-tree portfast [edge] bpduguard default
```
**Modus:** Interface bzw. global. Eine empfangene BPDU setzt den Port in err-disabled.
T: Befehl Mittel

Q: Wie unterdrückst du BPDUs auf PortFast-Ports, fällst aber bei einer empfangenen BPDU auf normales STP zurück?
A:
```
spanning-tree portfast [edge] bpdufilter default
```
**Modus:** global. Falle: Am Interface (`spanning-tree bpdufilter enable`) filtert BPDU Filter alles in beide Richtungen und kann Schleifen erzeugen.
T: Befehl Schwer

Q: Wie verhinderst du, dass ein angeschlossener Switch die Root Bridge übernimmt?
A:
```
spanning-tree guard root
```
**Modus:** Interface, auf Ports Richtung Access. Bessere BPDUs setzen den Port in „root-inconsistent“.
T: Befehl Mittel

Q: Wie schützt du einen blockierten Port davor, in Forwarding zu gehen, wenn plötzlich keine BPDUs mehr kommen?
A:
```
spanning-tree guard loop
```
**Modus:** Interface. Global für alle Ports: `spanning-tree loopguard default`. Der Port geht in „loop-inconsistent“.
T: Befehl Schwer

Q: Wie erkennst du unidirektionale Glasfaserlinks und schaltest sie ab?
A:
```
udld aggressive
interface <interface>
 udld port aggressive
```
**Modus:** global (für Glasfaser) bzw. Interface. Im Aggressive Mode geht der Port in err-disabled, sobald keine Echos zurückkommen.
T: Befehl Schwer

Q: Wie holst du Ports automatisch aus err-disabled zurück, z. B. nach BPDU Guard?
A:
```
errdisable recovery cause bpduguard
errdisable recovery interval <sekunden>
```
**Modus:** global. Prüfen mit `show errdisable recovery`.
T: Befehl Mittel

Q: Welcher Befehl zeigt für ein VLAN Root Bridge, eigene Bridge-ID und Rolle, Zustand und Kosten jedes Ports?
A:
```
show spanning-tree vlan <vlan-id>
```
**Modus:** privilegiert. Rollen: Root, Desg, Altn, Back. Zustände: FWD, BLK, LRN.
T: Befehl Leicht

Q: Welcher Befehl zeigt für alle VLANs die Root Bridge, die Kosten dorthin und den Root Port?
A:
```
show spanning-tree root
```
**Modus:** privilegiert. Kosten 0 und kein Root Port heißt: Dieser Switch ist selbst Root.
T: Befehl Mittel

Q: Welcher Befehl zeigt pro VLAN, wann die letzte Topologieänderung war und von welchem Port sie kam?
A:
```
show spanning-tree detail
```
**Modus:** privilegiert. Häufige Topology Changes deuten auf flappende Ports ohne PortFast hin.
T: Befehl Schwer

Q: Welcher Befehl zeigt alle Ports, die Root Guard oder Loop Guard gerade blockiert?
A:
```
show spanning-tree inconsistentports
```
**Modus:** privilegiert. Leere Ausgabe heißt: keine Inkonsistenzen.
T: Befehl Mittel

Q: Wie änderst du die STP-Timer eines VLANs auf der Root Bridge?
A:
```
spanning-tree vlan <vlan-id> {hello-time | forward-time | max-age} <sekunden>
```
**Modus:** global. Nur die Root verteilt ihre Timer, Einstellungen auf anderen Switches wirken erst, wenn sie Root werden.
T: Befehl Schwer

# 3.1.c | Befehle: MST
S: https://www.cisco.com/c/en/us/support/switches/catalyst-9300-series-switches/products-command-reference-list.html | Cisco Catalyst 9300: Command References

Q: Wie konfigurierst du MST-Region, Revision und die Zuordnung von VLANs zu einer Instanz?
A:
```
spanning-tree mst configuration
 name <region>
 revision <nummer>
 instance <nr> vlan <vlan-liste>
```
**Modus:** global, dann MST-Konfiguration. Name, Revision und Zuordnung müssen auf allen Switches der Region identisch sein.
T: Befehl Mittel

Q: Wie machst du einen Switch zur Root einer MST-Instanz?
A:
```
spanning-tree mst <instanz> root {primary | secondary}
```
**Modus:** global. Direkt geht es mit `spanning-tree mst <instanz> priority <wert>`.
T: Befehl Mittel

Q: Wie änderst du unter MST die Kosten eines Ports für eine Instanz?
A:
```
spanning-tree mst <instanz> cost <kosten>
```
**Modus:** Interface. Analog `spanning-tree mst <instanz> port-priority <wert>`.
T: Befehl Schwer

Q: Welcher Befehl zeigt Region, Revision und die VLAN-Zuordnung der MST-Instanzen?
A:
```
show spanning-tree mst configuration
```
**Modus:** privilegiert. Vor dem Verlassen der MST-Konfiguration zeigt `show pending` die noch nicht aktiven Änderungen.
T: Befehl Mittel

Q: Welcher Befehl zeigt pro MST-Instanz Root und Port-Rollen?
A:
```
show spanning-tree mst [<instanz>]
```
**Modus:** privilegiert. Instanz 0 ist die IST, sie spricht mit Switches außerhalb der Region.
T: Befehl Mittel

# 3.2.b | Befehle: OSPFv2
S: https://www.cisco.com/c/en/us/support/ios-nx-os-software/ios-xe-17/products-command-reference-list.html | Cisco IOS XE 17: Command References

Q: Wie startest du OSPF mit fester Router-ID?
A:
```
router ospf <prozess-id>
 router-id <a.b.c.d>
```
**Modus:** global, dann Router. Ohne feste ID nimmt OSPF die höchste Loopback- oder Interface-Adresse beim Start.
T: Befehl Leicht

Q: Wie aktivierst du OSPF mit dem `network`-Befehl für ein Netz in einer Area?
A:
```
network <adresse> <wildcard> area <area-id>
```
**Modus:** Router. Jedes Interface, dessen Adresse passt, wird aktiv. `network 0.0.0.0 255.255.255.255 area 0` trifft alle.
T: Befehl Leicht

Q: Wie aktivierst du OSPF direkt auf einem Interface?
A:
```
ip ospf <prozess-id> area <area-id>
```
**Modus:** Interface. Hat Vorrang vor einem passenden `network`-Befehl.
T: Befehl Leicht

Q: Wie machst du alle Interfaces passiv und nimmst nur die Uplinks wieder heraus?
A:
```
router ospf <prozess-id>
 passive-interface default
 no passive-interface <uplink>
```
**Modus:** Router. Passive Interfaces senden keine Hellos, ihr Netz wird aber weiter beworben.
T: Befehl Mittel

Q: Wie setzt du die OSPF-Kosten eines Interfaces?
A:
```
ip ospf cost <1-65535>
```
**Modus:** Interface. Sonst gilt: Referenzbandbreite geteilt durch Interface-Bandbreite.
T: Befehl Leicht

Q: Wie setzt du die OSPF-Referenzbandbreite auf 100 Gbit/s?
A:
```
auto-cost reference-bandwidth 100000
```
**Modus:** Router. Wert in Mbit/s. Muss auf allen Routern gleich sein, sonst werden die Pfade uneinheitlich bewertet.
T: Befehl Mittel

Q: Wie beeinflusst du die DR-Wahl auf einem Ethernet-Segment?
A:
```
ip ospf priority <0-255>
```
**Modus:** Interface. 0 heißt: nie DR oder BDR. Die Wahl ist nicht preemptiv.
T: Befehl Mittel

Q: Wie änderst du den OSPF-Netzwerktyp eines Interfaces?
A:
```
ip ospf network {point-to-point | broadcast | point-to-multipoint | non-broadcast}
```
**Modus:** Interface. Die Typen müssen nicht gleich sein, aber die Hello- und Dead-Timer der Typen müssen passen.
T: Befehl Mittel

Q: Wie stellst du die OSPF-Timer eines Interfaces auf schnellere Erkennung ein?
A:
```
ip ospf hello-interval <sekunden>
ip ospf dead-interval <sekunden>
```
**Modus:** Interface. Beide Nachbarn brauchen dieselben Werte. Subsekunden-Hellos: `ip ospf dead-interval minimal hello-multiplier 4`.
T: Befehl Mittel

Q: Wie fasst du auf einem ABR die Netze einer Area zu einem Summary zusammen?
A:
```
area <area-id> range <netz> <maske>
```
**Modus:** Router (auf dem ABR). Fasst Typ-1- und Typ-2-LSAs der Area zu einem Typ-3-LSA zusammen.
T: Befehl Mittel

Q: Wie fasst du auf einem ASBR redistribuierte externe Netze zusammen?
A:
```
summary-address <netz> <maske>
```
**Modus:** Router (auf dem ASBR). Wirkt auf Typ-5- und Typ-7-LSAs, nicht auf interne Routen.
T: Befehl Schwer

# 3.3.d | Befehle: Multicast

Q: Wie schaltest du Multicast-Routing auf einem Router ein?
A:
```
ip multicast-routing [distributed]
```
**Modus:** global. Auf vielen Catalyst-Plattformen ist `distributed` Pflicht.
T: Befehl Leicht

Q: Wie aktivierst du PIM Sparse Mode auf einem Interface?
A:
```
ip pim sparse-mode
```
**Modus:** Interface. Auf allen Interfaces im Multicast-Pfad, auch auf Loopbacks, die als RP dienen.
T: Befehl Leicht

Q: Wie legst du einen statischen Rendezvous Point fest?
A:
```
ip pim rp-address <rp-ip> [<acl>]
```
**Modus:** global, auf allen Routern gleich. Die ACL beschränkt die Gruppen, für die dieser RP gilt.
T: Befehl Mittel

Q: Wie meldet sich ein Router per Auto-RP als RP-Kandidat und wie wird ein anderer zum Mapping Agent?
A:
```
ip pim send-rp-announce Loopback0 scope <ttl>
ip pim send-rp-discovery Loopback0 scope <ttl>
```
**Modus:** global. Kandidaten senden an 224.0.1.39, der Mapping Agent verteilt an 224.0.1.40.
T: Befehl Schwer

Q: Wie konfigurierst du einen Router als BSR- und RP-Kandidat?
A:
```
ip pim bsr-candidate Loopback0
ip pim rp-candidate Loopback0
```
**Modus:** global. BSR ist der Standard (PIMv2) und flutet die RP-Informationen hop für hop.
T: Befehl Schwer

Q: Wie aktivierst du Source-Specific Multicast für den Standardbereich 232/8?

**Modus:** global. Die Empfänger brauchen IGMPv3: `ip igmp version 3` am Interface.
T: Befehl Schwer

Q: Wie lässt du ein Router-Interface einer Multicast-Gruppe beitreten, um Multicast zu testen?
