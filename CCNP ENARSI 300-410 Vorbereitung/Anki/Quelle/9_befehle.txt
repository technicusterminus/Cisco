# 1.1 | Befehle: Administrative Distance
S: https://www.cisco.com/c/en/us/support/ios-nx-os-software/ios-xe-17/products-command-reference-list.html | Cisco IOS XE 17: Command References

Q: Wie änderst du die Administrative Distance aller OSPF-Routen auf einem Router?
A:
```
router ospf <prozess-id>
 distance <ad>
```
**Modus:** Router. Getrennt nach Routentyp geht es mit `distance ospf intra-area <ad> inter-area <ad> external <ad>`.
T: Befehl Mittel

Q: Wie setzt du in EIGRP unterschiedliche Distanzen für interne und externe Routen?
A:
```
router eigrp <as>
 distance eigrp <intern> <extern>
```
**Modus:** Router (Classic). Standard: 90 intern, 170 extern. Im Named Mode unter `topology base`.
T: Befehl Mittel

Q: Wie änderst du die Distanzen für eBGP-, iBGP- und lokale BGP-Routen?
A:
```
router bgp <as>
 distance bgp <ebgp> <ibgp> <lokal>
```
**Modus:** Router. Standard: 20, 200, 200.
T: Befehl Mittel

Q: Wie änderst du die Distanz nur für Routen, die von einem bestimmten Nachbarn kommen?
A:
```
distance <ad> <quell-ip> <wildcard> [<acl>]
```
**Modus:** Router. Bei OSPF ist die Quelle die Router-ID des Absenders, bei EIGRP die Nachbaradresse.
T: Befehl Schwer

Q: Wie legst du eine statische Route an, die nur als Backup gilt?
A:
```
ip route <zielnetz> <maske> <next-hop-ip> <ad>
```
**Modus:** global. Die Distanz muss höher sein als die der dynamischen Route.
T: Befehl Leicht

# 1.2 | Befehle: Route-Maps, Prefix-Lists und Tags
S: https://www.cisco.com/c/en/us/support/ios-nx-os-software/ios-xe-17/products-command-reference-list.html | Cisco IOS XE 17: Command References

Q: Wie legst du eine Prefix-Liste an, die genau ein Netz mit genau dieser Länge erlaubt?
A:
```
ip prefix-list <name> seq <nr> permit <netz>/<länge>
```
**Modus:** global. Ohne `ge` oder `le` muss die Präfixlänge exakt passen.
T: Befehl Leicht

Q: Wie legst du eine Prefix-Liste an, die alle Präfixe erlaubt?
A:
```
ip prefix-list <name> seq <nr> permit 0.0.0.0/0 le 32
```
**Modus:** global. Typisch als letzte Zeile nach einigen `deny`-Einträgen. Nur `0.0.0.0/0` allein trifft nur die Default-Route.
T: Befehl Mittel

Q: Wie gleichst du in einer Route-Map Routen gegen eine Prefix-Liste ab?
A:
```
route-map <name> permit <seq>
 match ip address prefix-list <liste>
```
**Modus:** Route-Map. Ohne `prefix-list` erwartet `match ip address` eine ACL.
T: Befehl Leicht

Q: Wie markierst du Routen in einer Route-Map mit einem Tag?
A:
```
route-map <name> permit <seq>
 set tag <wert>
```
**Modus:** Route-Map. Tags überleben die Redistribution und helfen, Routing-Schleifen zu erkennen.
T: Befehl Mittel

Q: Wie filterst du in einer Route-Map Routen mit einem bestimmten Tag heraus?
A:
```
route-map <name> deny <seq>
 match tag <wert>
route-map <name> permit <seq>
```
**Modus:** Route-Map. Der leere `permit`-Eintrag am Ende lässt alles andere durch, sonst greift das implizite deny.
T: Befehl Mittel

Q: Wie setzt du in einer Route-Map Metrik und Metriktyp für redistribuierte OSPF-Routen?
A:
```
route-map <name> permit <seq>
 set metric <wert>
 set metric-type {type-1 | type-2}
```
**Modus:** Route-Map. E1 addiert die internen Kosten zum ASBR, E2 (Standard) nicht.
T: Befehl Mittel

Q: Wie lässt du eine Route-Map nach einem Treffer mit dem nächsten Eintrag weitermachen?
A:
```
route-map <name> permit <seq>
 match <bedingung>
 set <aktion>
 continue [<seq>]
```
**Modus:** Route-Map. Ohne `continue` endet die Auswertung beim ersten Treffer.
T: Befehl Schwer

Q: Welcher Befehl zeigt eine Route-Map mit ihren Treffern?
A:
```
show route-map [<name>]
```
**Modus:** privilegiert. Prefix-Listen mit Treffern: `show ip prefix-list detail [<name>]`.
T: Befehl Leicht

# 1.3 | Befehle: Filterung und Loop-Prevention
S: https://www.cisco.com/c/en/us/support/ios-nx-os-software/ios-xe-17/products-command-reference-list.html | Cisco IOS XE 17: Command References

Q: Wie filterst du Routen, die ein Routing-Protokoll lernt oder bewirbt, mit einer Prefix-Liste?
A:
```
distribute-list prefix <liste> {in | out} [<interface>]
```
**Modus:** Router. Bei OSPF wirkt `in` nur auf die RIB, `out` nur am ASBR auf redistribuierte Routen.
T: Befehl Mittel

Q: Wie filterst du mit einer Route-Map Routen, die OSPF in die RIB übernimmt?
A:
```
router ospf <prozess-id>
 distribute-list route-map <name> in
```
**Modus:** Router. Die Route-Map kann auf Tag, Metrik oder Next Hop prüfen.
T: Befehl Schwer

Q: Wie schaltest du EIGRP Split Horizon auf einem Interface ab?
A:
```
no ip split-horizon eigrp <as>
```
**Modus:** Interface (Classic). Im Named Mode: `af-interface <interface>` und `no split-horizon`. Nötig auf einem DMVPN-Hub.
T: Befehl Mittel

Q: Wie erhöhst du die EIGRP-Metrik bestimmter Routen, die über ein Interface ankommen?
A:
```
offset-list <acl> in <offset> <interface>
```
**Modus:** Router. Macht einen Pfad unattraktiver, ohne Bandbreite oder Delay zu ändern.
T: Befehl Schwer

# 1.4 | Befehle: Redistribution
S: https://www.cisco.com/c/en/us/support/ios-nx-os-software/ios-xe-17/products-command-reference-list.html | Cisco IOS XE 17: Command References

Q: Wie redistribuierst du OSPF in EIGRP mit einer Seed-Metrik?
A:
```
router eigrp <as>
 redistribute ospf <prozess-id> metric <bandbreite> <delay> <zuverlässigkeit> <last> <mtu>
```
**Modus:** Router. Beispiel: `metric 100000 100 255 1 1500`. Ohne Metrik übernimmt EIGRP externe Routen nicht (außer von EIGRP, statisch, connected).
T: Befehl Mittel

Q: Wie setzt du eine Standardmetrik für alle redistribuierten Routen in EIGRP?
A:
```
default-metric <bandbreite> <delay> <zuverlässigkeit> <last> <mtu>
```
**Modus:** Router. Gilt für jedes `redistribute` ohne eigene Metrik.
T: Befehl Mittel

Q: Wie redistribuierst du EIGRP in OSPF als E1-Routen mit fester Metrik?
A:
```
router ospf <prozess-id>
 redistribute eigrp <as> subnets metric <kosten> metric-type 1
```
**Modus:** Router. `subnets` ist auf neueren Versionen Standard, auf älteren fehlen ohne es alle Subnetze.
T: Befehl Mittel

Q: Wie redistribuierst du OSPF in BGP, einschließlich der externen OSPF-Routen?
A:
```
router bgp <as>
 redistribute ospf <prozess-id> match internal external 1 external 2
```
**Modus:** Router bzw. Address Family. Ohne `match` übernimmt BGP nur interne OSPF-Routen.
T: Befehl Schwer

Q: Wie redistribuierst du nur die Netze aus einer Route-Map?
A:
```
redistribute <protokoll> [<id>] route-map <name>
```
**Modus:** Router. Alles, was die Route-Map nicht erlaubt, wird nicht redistribuiert.
T: Befehl Mittel

Q: Wie nimmst du bei OSPFv3 auch die Connected-Netze des Quellprotokolls mit in die Redistribution?
A:
```
redistribute eigrp <as> include-connected
```
**Modus:** Address Family (OSPFv3, IPv6). Bei IPv6 sind die Interfaces, auf denen das Quellprotokoll läuft, sonst nicht dabei.
T: Befehl Schwer

Q: Welcher Befehl zeigt die externen Routen in der OSPF-Datenbank mit Metriktyp und Tag?
A:
```
show ip ospf database external [<präfix>]
```
**Modus:** privilegiert. „Metric Type: 1“ oder „2“ und „External Route Tag“ stehen pro LSA.
T: Befehl Mittel

# 1.5 | Befehle: Summarization
S: https://www.cisco.com/c/en/us/support/ios-nx-os-software/ios-xe-17/products-command-reference-list.html | Cisco IOS XE 17: Command References

Q: Wie fasst du in EIGRP Classic Mode Routen auf einem Interface zusammen?
A:
```
interface <interface>
 ip summary-address eigrp <as> <netz> <maske>
```
**Modus:** Interface. EIGRP legt dabei eine Discard-Route auf Null0 mit AD 5 an.
T: Befehl Mittel

Q: Wie fasst du im EIGRP Named Mode Routen zusammen?
A:
```
router eigrp <name>
 address-family ipv4 unicast autonomous-system <as>
  af-interface <interface>
   summary-address <netz> <maske>
```
**Modus:** AF-Interface. Gilt nur für Updates aus diesem Interface heraus.
T: Befehl Mittel

Q: Wie fasst du auf einem OSPF-ABR die Netze einer Area zusammen, oder unterdrückst sie ganz?
A:
```
area <area-id> range <netz> <maske> [not-advertise] [cost <kosten>]
```
**Modus:** Router (ABR). `not-advertise` filtert die Netze, statt sie zusammengefasst zu bewerben.
T: Befehl Mittel

Q: Wie fasst du auf einem OSPF-ASBR externe Routen zusammen?
A:
```
summary-address <netz> <maske> [not-advertise]
```
**Modus:** Router (ASBR). Gilt für Typ-5- und Typ-7-LSAs.
T: Befehl Mittel

Q: Wie fasst du in BGP zusammen und behältst dabei die AS-Pfad-Information der Einzelrouten?
A:
```
aggregate-address <netz> <maske> summary-only as-set
```
**Modus:** Router bzw. Address Family. `as-set` verhindert Schleifen, macht das Aggregat aber bei jeder Änderung eines Einzelpfads instabil.
T: Befehl Schwer

Q: Wie unterdrückst du beim BGP-Aggregat nur bestimmte Einzelrouten?
A:
```
aggregate-address <netz> <maske> suppress-map <route-map>
```
**Modus:** Router. Routen, die die Route-Map erlaubt, werden unterdrückt, der Rest bleibt sichtbar.
T: Befehl Schwer

# 1.6 | Befehle: Policy-Based Routing
S: https://www.cisco.com/c/en/us/support/ios-nx-os-software/ios-xe-17/products-command-reference-list.html | Cisco IOS XE 17: Command References

Q: Wie leitest du Verkehr aus einer ACL per PBR an einen anderen Next Hop?
A:
```
route-map <name> permit 10
 match ip address <acl>
 set ip next-hop <ip>
interface <eingangs-interface>
 ip policy route-map <name>
```
**Modus:** global bzw. Interface. PBR greift nur eingehend.
T: Befehl Mittel

Q: Wie schickt PBR Verkehr nur dann zum gewünschten Next Hop, wenn kein genauerer Eintrag in der Routing-Tabelle steht?
A:
```
set ip default next-hop <ip>
```
**Modus:** Route-Map. Die Routing-Tabelle hat Vorrang, PBR ersetzt nur die Default-Route.
T: Befehl Schwer

Q: Wie verwirfst du Verkehr per PBR?
A:
```
set interface Null0
```
**Modus:** Route-Map. Gut, um z. B. eine Quelle gezielt zu blockieren, ohne eine ACL am Interface.
T: Befehl Schwer

Q: Wie wendest du PBR auf vom Router selbst erzeugten Verkehr an?
A:
```
ip local policy route-map <name>
```
**Modus:** global. Wirkt z. B. auf IP-SLA-Pakete, die einen bestimmten Weg nehmen sollen.
T: Befehl Schwer

Q: Wie verfolgst du live, welche Pakete PBR trifft?
A:
```
debug ip policy
```
**Modus:** privilegiert. Zählerstände ohne Debug: `show route-map <name>`.
T: Befehl Mittel

# 1.7 | Befehle: VRF-Lite
S: https://www.cisco.com/c/en/us/support/ios-nx-os-software/ios-xe-17/products-command-reference-list.html | Cisco IOS XE 17: Command References

Q: Wie legst du eine VRF an und ordnest ein Interface zu?
A:
```
vrf definition <name>
 address-family ipv4
interface <interface>
 vrf forwarding <name>
 ip address <ip-adresse> <maske>
```
**Modus:** global bzw. Interface. `vrf forwarding` löscht eine vorhandene IP-Adresse am Interface.
T: Befehl Mittel

Q: Wie startest du OSPF in einer VRF auf einem Router, der kein PE ist?
A:
```
router ospf <prozess-id> vrf <name>
 capability vrf-lite
```
**Modus:** global, dann Router. Ohne `capability vrf-lite` behandelt OSPF den Router wie einen PE und prüft das Down-Bit.
T: Befehl Schwer

Q: Wie startest du EIGRP für eine VRF im Named Mode?
A:
```
router eigrp <name>
 address-family ipv4 unicast vrf <vrf> autonomous-system <as>
  network <netz> <wildcard>
```
**Modus:** Router. Im Classic Mode: `address-family ipv4 vrf <vrf>` und darunter `autonomous-system <as>`.
T: Befehl Schwer

Q: Wie leitest du per statischer Route aus einer VRF in die globale Tabelle (Route Leaking)?
A:
```
ip route vrf <name> <zielnetz> <maske> <next-hop-ip> global
```
**Modus:** global. `global` sagt: Der Next Hop wird in der globalen Tabelle aufgelöst.
T: Befehl Schwer

Q: Wie leitest du aus der globalen Tabelle in eine VRF?
A:
```
ip route <zielnetz> <maske> <vrf-interface> <next-hop-ip>
```
**Modus:** global. Das Ausgangsinterface gehört zur VRF, deshalb landet der Verkehr dort.
T: Befehl Schwer

Q: Welche Befehle prüfen VRF-Zuordnung, Routing-Tabelle und Erreichbarkeit einer VRF?
A:
```
show vrf
show ip route vrf <name>
ping vrf <name> <ziel>
```
**Modus:** privilegiert. Fast jeder Show-Befehl kennt den Zusatz `vrf <name>`.
T: Befehl Leicht

# 1.8 | Befehle: BFD
S: https://www.cisco.com/c/en/us/support/ios-nx-os-software/ios-xe-17/products-command-reference-list.html | Cisco IOS XE 17: Command References

Q: Wie stellst du BFD-Intervalle auf einem Interface ein?
A:
```
bfd interval <ms> min_rx <ms> multiplier <anzahl>
```
**Modus:** Interface. Beispiel `bfd interval 50 min_rx 50 multiplier 3`: Ausfall nach 150 ms erkannt.
T: Befehl Mittel

Q: Wie meldet sich OSPF bei BFD an?
A:
```
router ospf <prozess-id>
 bfd all-interfaces
```
**Modus:** Router. Nur für ein Interface: `ip ospf bfd` am Interface.
T: Befehl Mittel

Q: Wie meldet sich EIGRP bei BFD an?
A:
```
router eigrp <as>
 bfd all-interfaces
```
**Modus:** Router (Classic). Im Named Mode: `af-interface <interface>` und `bfd`.
T: Befehl Mittel

Q: Wie koppelst du eine BGP-Sitzung an BFD?
A:
```
neighbor <peer-ip> fall-over bfd
```
**Modus:** Router. BGP baut die Sitzung ab, sobald BFD den Nachbarn verliert, statt auf den Hold-Timer zu warten.
T: Befehl Mittel

Q: Wie überwachst du den Next Hop einer statischen Route mit BFD?
A:
```
ip route static bfd <interface> <next-hop-ip>
ip route <zielnetz> <maske> <interface> <next-hop-ip>
```
**Modus:** global. Fällt die BFD-Sitzung, nimmt der Router die statische Route aus der RIB.
T: Befehl Schwer

Q: Welcher Befehl zeigt die BFD-Sitzungen mit Zustand und Intervallen?
A:
```
show bfd neighbors [details]
```
**Modus:** privilegiert. `details` zeigt auch, welche Protokolle die Sitzung nutzen.
T: Befehl Leicht

# 1.9.a | Befehle: EIGRP Named Mode und IPv6
S: https://www.rfc-editor.org/rfc/rfc7868 | RFC 7868: Cisco's Enhanced Interior Gateway Routing Protocol

Q: Wie richtest du EIGRP im Named Mode für IPv4 mit Router-ID ein?
A:
```
router eigrp <name>
 address-family ipv4 unicast autonomous-system <as>
  eigrp router-id <a.b.c.d>
  network <netz> <wildcard>
```
**Modus:** global, dann Address Family. Ein Named-Mode-Prozess kann IPv4 und IPv6 gleichzeitig tragen.
T: Befehl Mittel

Q: Wie schaltest du im EIGRP Named Mode alle Interfaces passiv und nur eines aktiv?
A:
```
af-interface default
 passive-interface
af-interface <uplink>
 no passive-interface
```
**Modus:** Address Family. Passive Interfaces senden keine Hellos.
T: Befehl Mittel

Q: Wo stellst du im EIGRP Named Mode Variance, Maximum-Paths und Redistribution ein?
A:
```
router eigrp <name>
 address-family ipv4 unicast autonomous-system <as>
  topology base
   variance <n>
   maximum-paths <n>
   redistribute <protokoll> ...
```
**Modus:** Topology Base. Alles, was die Routing-Tabelle betrifft, steht hier, nicht direkt in der Address Family.
T: Befehl Schwer

Q: Wie aktivierst du EIGRP für IPv6 im Classic Mode?
A:
```
ipv6 router eigrp <as>
 eigrp router-id <a.b.c.d>
interface <interface>
 ipv6 eigrp <as>
```
**Modus:** global bzw. Interface. Es gibt keinen `network`-Befehl für IPv6.
T: Befehl Mittel

Q: Welche Befehle zeigen EIGRP-Nachbarn und Topologie für IPv6?
A:
```
show ipv6 eigrp neighbors
show ipv6 eigrp topology
```
**Modus:** privilegiert. Für den Named Mode allgemein: `show eigrp address-family ipv6 neighbors`.
T: Befehl Mittel

# 1.9.b | Befehle: EIGRP-Nachbarschaft und Authentisierung
S: https://www.rfc-editor.org/rfc/rfc7868 | RFC 7868: Cisco's Enhanced Interior Gateway Routing Protocol

Q: Wie setzt du EIGRP-Hello- und Hold-Timer auf einem Interface im Classic Mode?
A:
```
ip hello-interval eigrp <as> <sekunden>
ip hold-time eigrp <as> <sekunden>
```
**Modus:** Interface. Die Werte müssen nicht zum Nachbarn passen, die Hold-Zeit wird mitgeteilt.
T: Befehl Mittel

Q: Wie aktivierst du EIGRP-Authentisierung mit MD5 im Classic Mode?
A:
```
key chain <kc>
 key 1
  key-string <schlüssel>
interface <interface>
 ip authentication mode eigrp <as> md5
 ip authentication key-chain eigrp <as> <kc>
```
**Modus:** global bzw. Interface. Beide Zeilen am Interface sind nötig.
T: Befehl Mittel

Q: Wie aktivierst du EIGRP-Authentisierung mit HMAC-SHA-256 im Named Mode?
A:
```
af-interface <interface>
 authentication mode hmac-sha-256 <passwort>
```
**Modus:** AF-Interface. SHA-256 gibt es nur im Named Mode.
T: Befehl Schwer

Q: Wie lässt du einen Schlüssel einer Key Chain nur in einem Zeitfenster gelten?
A:
```
key chain <kc>
 key <id>
  key-string <schlüssel>
  accept-lifetime <start> {infinite | <ende>}
  send-lifetime <start> {infinite | <ende>}
```
**Modus:** Key Chain. Für einen Schlüsselwechsel ohne Ausfall überlappen die Zeitfenster. Die Uhren müssen per NTP stimmen.
T: Befehl Schwer

Q: Welcher Befehl zeigt die Schlüssel einer Key Chain und welche gerade gültig sind?
A:
```
show key chain [<kc>]
```
**Modus:** privilegiert. „[valid now]“ markiert die aktiven Schlüssel.
T: Befehl Mittel

Q: Welcher Befehl zeigt die EIGRP-Nachbarn im Named Mode?
A:
```
show eigrp address-family ipv4 neighbors
```
**Modus:** privilegiert. `show ip eigrp neighbors` funktioniert auch für Named Mode.
T: Befehl Leicht

Q: Wie protokolliert EIGRP jede Änderung einer Nachbarschaft im Syslog?
A:
```
eigrp log-neighbor-changes
```
**Modus:** Router bzw. Address Family. Auf neueren Versionen Standard.
T: Befehl Leicht

# 1.9.f | Befehle: EIGRP-Metrik
S: https://www.rfc-editor.org/rfc/rfc7868 | RFC 7868: Cisco's Enhanced Interior Gateway Routing Protocol

Q: Wie änderst du die Bandbreite, mit der EIGRP auf einem Interface rechnet?
A:
```
bandwidth <kbit/s>
```
**Modus:** Interface. Ändert nur die Berechnung, nicht die echte Geschwindigkeit. OSPF und QoS nutzen den Wert auch.
T: Befehl Leicht

**Modus:** DHCP-Pool. Beliebige Optionen gehen nach demselben Muster, z. B. `option 43 hex <wert>` für WLAN-Controller.
T: Befehl Mittel

Q: Wie leitest du DHCP-Broadcasts an einen entfernten Server weiter?
A:
```
interface <client-gateway>
 ip helper-address <server-ip>
```
**Modus:** Interface. Der Relay setzt seine Adresse als giaddr, daran erkennt der Server den richtigen Pool.
T: Befehl Leicht

Q: Welche Befehle zeigen Leases und Adresskonflikte des DHCP-Servers?
A:
```
show ip dhcp binding
show ip dhcp conflict
```
**Modus:** privilegiert. Konflikte entstehen, wenn der Server vor der Vergabe per Ping eine Antwort bekommt.
T: Befehl Mittel

Q: Wie löschst du alle DHCP-Leases oder alle gemeldeten Konflikte?
A:
```
clear ip dhcp binding *
clear ip dhcp conflict *
```
**Modus:** privilegiert. Konfliktadressen werden sonst nicht wieder vergeben.
T: Befehl Mittel

Q: Mit welchem Debug verfolgst du, was der DHCP-Server tut?
A:
```
debug ip dhcp server events
```
**Modus:** privilegiert. Für die einzelnen Pakete: `debug ip dhcp server packet`.
T: Befehl Mittel

# 4.4 | Befehle: DHCP für IPv6
S: https://www.rfc-editor.org/rfc/rfc8415 | RFC 8415: Dynamic Host Configuration Protocol for IPv6

Q: Wie legst du einen stateful DHCPv6-Pool an und bindest ihn an ein Interface?
A:
```
ipv6 dhcp pool <name>
 address prefix <präfix>/64
 dns-server <ipv6-dns>
interface <interface>
 ipv6 dhcp server <name>
 ipv6 nd managed-config-flag
```
**Modus:** global bzw. Interface. Das M-Flag im RA sagt den Clients, dass sie die Adresse per DHCPv6 holen sollen.
T: Befehl Schwer

Q: Wie verteilst du per Stateless DHCPv6 nur DNS-Server, während die Adressen per SLAAC entstehen?

ipv6 dhcp pool <name>
 dns-server <ipv6-dns>
interface <interface>
 ipv6 dhcp server <name>
 ipv6 nd other-config-flag
```
**Modus:** global bzw. Interface. Das O-Flag heißt: weitere Informationen per DHCPv6.
T: Befehl Schwer

Q: Wie leitest du DHCPv6-Anfragen an einen Server in einem anderen Netz weiter?
A:
```
ipv6 dhcp relay destination <server-ipv6>
```
**Modus:** Interface. Das IPv6-Gegenstück zu `ip helper-address`.
T: Befehl Mittel

Q: Welcher Befehl zeigt die vergebenen DHCPv6-Bindungen?
A:

show ipv6 dhcp binding
```
**Modus:** privilegiert. Die Pools zeigt `show ipv6 dhcp pool`.
T: Befehl Mittel

# 4.5 | Befehle: IP SLA und Object Tracking
S: https://www.cisco.com/c/en/us/support/ios-nx-os-software/ios-xe-17/products-command-reference-list.html | Cisco IOS XE 17: Command References

Q: Wie legst du eine IP-SLA-ICMP-Messung an und startest sie dauerhaft?
A:
```
ip sla <nr>
 icmp-echo <ziel> source-interface <interface>
 frequency <sekunden>
ip sla schedule <nr> life forever start-time now
```
**Modus:** global. Ohne Schedule läuft die Messung nicht.
T: Befehl Mittel

Q: Wie prüfst du per IP SLA, ob ein Webserver antwortet?
A:
```
ip sla <nr>
 http get <url>
```
**Modus:** IP SLA. Misst DNS-Auflösung, TCP-Aufbau und Antwortzeit.
T: Befehl Schwer

Q: Wie verknüpfst du zwei Tracking-Objekte, sodass nur beide zusammen „up“ ergeben?
A:
```
track <nr> list boolean and
 object <objekt-1>
 object <objekt-2>
```
**Modus:** global, dann Track. Mit `or` reicht eines der Objekte.
T: Befehl Schwer

Q: Wie überwachst du, ob eine Route in der Routing-Tabelle steht?
A:
```
track <nr> ip route <netz>/<länge> reachability
```
**Modus:** global. Das Objekt ist up, solange die Route existiert.
T: Befehl Mittel

Q: Wie schaltest du per Tracking auf eine Backup-Default-Route um?
A:
```
ip route 0.0.0.0 0.0.0.0 <primär> track <nr>
ip route 0.0.0.0 0.0.0.0 <backup> <ad>
```
**Modus:** global. Ist das Objekt down, verschwindet die erste Route und die Floating Route greift.
T: Befehl Mittel

Q: Welche Befehle zeigen IP-SLA-Ergebnisse und Tracking-Zustände?
A:
```
show ip sla statistics [<nr>]
show track [brief]
```
**Modus:** privilegiert. Bei „Timeout“ oder „No connection“ steht der Grund im Return Code.
T: Befehl Leicht

# 4.6 | Befehle: NetFlow und IPFIX
S: https://www.rfc-editor.org/rfc/rfc7011 | RFC 7011: IPFIX Protocol Specification

Q: Wie legst du einen Flow Exporter für IPFIX an?
A:
```
flow exporter <name>
 destination <collector-ip>
 source <interface>
 transport udp <port>
 export-protocol ipfix
```
**Modus:** global, dann Flow Exporter. Standard wäre NetFlow v9.
T: Befehl Mittel

Q: Wie legst du einen Flow Record mit 5-Tupel und Zählern an?
A:
```
flow record <name>
 match ipv4 source address
 match ipv4 destination address
 match ipv4 protocol
 match transport source-port
 match transport destination-port
 collect counter bytes long
 collect counter packets long
```
**Modus:** global, dann Flow Record. Die `match`-Felder bilden zusammen den Schlüssel eines Flows.
T: Befehl Schwer

Q: Wie verknüpfst du Record und Exporter und wendest den Monitor ausgehend an?
A:
```
flow monitor <name>
 record <record>
 exporter <exporter>
interface <interface>
 ip flow monitor <name> output
```
**Modus:** global bzw. Interface. Eingehend mit `input`. Beide Richtungen brauchen zwei Zeilen.
T: Befehl Mittel

Q: Wie nutzt du einen vordefinierten Flow Record, ohne einen eigenen zu bauen?
A:
```
flow monitor <name>
 record netflow ipv4 original-input
```
**Modus:** Flow Monitor. Entspricht dem klassischen NetFlow-v5-Inhalt.
T: Befehl Schwer

Q: Welche Befehle zeigen Flow-Cache, Exporter-Statistik und die Interfaces mit Flow Monitor?
A:
```
show flow monitor <name> cache
show flow exporter <name> statistics
show flow interface [<interface>]
```
**Modus:** privilegiert. Leerer Cache heißt meist: Monitor nicht oder in der falschen Richtung angewendet.
T: Befehl Mittel
